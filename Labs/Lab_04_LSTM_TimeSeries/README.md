# Прогнозирование временного ряда NASA SMAP с помощью LSTM

Проект представляет полный цикл работы с многомерным временным рядом спутниковой
телеметрии: от автоматического получения исходных данных до построения прогноза,
оценки качества модели и анализа аномальных участков.

В основе решения используется рекуррентная нейронная сеть LSTM, которая получает
последовательность предыдущих наблюдений и прогнозирует значения всех каналов на
следующем временном шаге.

## Датасет

Источник данных — [THULab/SMAP](https://huggingface.co/datasets/THULab/SMAP),
содержащий телеметрию спутника NASA Soil Moisture Active Passive.

Основные характеристики:

| Характеристика | Значение |
|---|---:|
| Обучающая часть | 135 183 временных шага |
| Тестовая часть | 427 617 временных шагов |
| Количество признаков | 25 каналов |
| Шаг временной оси | 1000 мс |
| Аномальные точки в train | 0 |
| Аномальные точки в test | 54 696 |
| Формат хранения | Apache TsFile |

Каждая строка содержит:

- `time` — последовательную временную отметку;
- `channel_0 … channel_24` — значения 25 каналов телеметрии;
- `label` — бинарную метку состояния: `0` для нормального наблюдения и `1` для
  аномалии.

Официальное разделение на train и test сохраняется без изменений. Метки
аномалий не используются как входные признаки и применяются только при итоговой
оценке.

## Возможности проекта

- автоматическая загрузка THULab/SMAP с Hugging Face;
- чтение файлов Apache TsFile;
- проверка структуры, размеров и временной оси;
- обработка пропущенных и бесконечных значений;
- стандартизация признаков без утечки информации из test;
- последовательное разделение train/validation/test;
- формирование временных окон без многократного копирования данных;
- прогноз всех 25 каналов с помощью LSTM;
- оценка качества прогноза по регрессионным метрикам;
- определение аномалий по величине ошибки прогнозирования;
- визуализация истории обучения, прогнозов и аномальных участков;
- сохранение обученной модели и результатов эксперимента.

## Установка

Для работы рекомендуется Python 3.11 или 3.12.

```bash
python -m venv .venv
```

Активация окружения в Windows:

```bash
.venv\Scripts\activate
```

Активация в Linux или macOS:

```bash
source .venv/bin/activate
```

Установка зависимостей:

```bash
pip install -r requirements.txt
```

## Запуск

Получение датасета:

```bash
python scripts/download_data.py
```

Подготовка выборок и создание модели с окном из 100 наблюдений:

```bash
python scripts/prepare_and_build.py --window 100
```

Размер validation-части можно изменить параметром:

```bash
python scripts/prepare_and_build.py --window 100 --validation-fraction 0.2
```

Загруженные данные сохраняются в `data/raw/` и не добавляются в Git.

## 1. Получение данных

Загрузчик получает два файла непосредственно из репозитория THULab/SMAP:

```text
data/raw/
├── SMAP_train.tsfile
└── SMAP_test.tsfile
```

Загрузка выполняется через временный файл с расширением `.part`. После завершения
проверяется сигнатура Apache TsFile, поэтому повреждённый или не полностью
загруженный файл не используется. При временной сетевой ошибке запрос повторяется
автоматически.

## 2. Предобработка

Файлы читаются официальным Python SDK Apache TsFile. Перед формированием выборок
выполняются следующие проверки и преобразования:

1. Проверяется наличие `time`, `label` и 25 колонок `channel_*`.
2. Проверяются ожидаемые размеры train и test.
3. Контролируется бинарный формат разметки `label`.
4. Проверяется равномерность временной оси с шагом 1000 мс.
5. Значения приводятся к типу `float32`.
6. Бесконечные значения преобразуются в пропуски.
7. Пропуски заменяются медианами соответствующих признаков.
8. Каждый канал стандартизуется с помощью `StandardScaler`.

Медианы, средние значения и стандартные отклонения вычисляются только по
обучающей части. Таким образом, информация из validation и test не влияет на
предобработку модели.

## 3. Подготовка выборок

Официальная тестовая выборка остаётся неизменной. Последние 20% обучающей части
используются как validation. Случайное перемешивание перед разделением не
применяется, поскольку оно нарушило бы временной порядок наблюдений.

При длине окна `W = 100` формируется задача:

```text
X[i] = значения 25 каналов за предыдущие 100 шагов
y[i] = значения 25 каналов на следующем шаге
```

Полученные формы:

```text
X_train: (108046, 100, 25)
y_train: (108046, 25)

X_val:   (26937, 100, 25)
y_val:   (26937, 25)

X_test:  (427517, 100, 25)
y_test:  (427517, 25)
```

Окна создаются функцией `numpy.sliding_window_view`. Она возвращает представление
над исходным массивом без физического копирования каждого окна. Это позволяет
работать с полной тестовой выборкой без выделения нескольких дополнительных
гигабайт оперативной памяти.

Для каждого тестового примера также сохраняются соответствующая временная метка
и правильная метка аномалии.

## 4. Архитектура LSTM

Используется следующая архитектура:

```text
Input(100, 25)
→ LSTM(64, return_sequences=True)
→ Dropout(0.2)
→ LSTM(32)
→ Dropout(0.2)
→ Dense(16, ReLU)
→ Dense(25, Linear)
```

Первый LSTM-слой формирует последовательность скрытых состояний, второй сводит
её к единому представлению временного окна. Полносвязный слой с `ReLU` выделяет
нелинейные зависимости, а последний линейный слой прогнозирует значения всех
25 каналов.

Параметры модели:

| Параметр | Значение |
|---|---|
| Количество обучаемых параметров | 36 409 |
| Оптимизатор | Adam |
| Функция потерь | Mean Squared Error |
| Дополнительная метрика | Mean Absolute Error |
| Dropout | 0.2 |

## 5. Обучение модели

Модель обучается на последовательностях из train, а качество после каждой эпохи
контролируется по validation. Временной порядок внутри последовательностей
сохраняется.

Для устойчивого обучения используются:

- контроль validation loss;
- ранняя остановка при отсутствии улучшения;
- восстановление весов лучшей эпохи;
- сохранение обученной модели;
- пакетная обработка данных для ограничения потребления памяти.

История обучения используется для анализа сходимости и выявления переобучения.

## 6. Прогнозирование и оценка качества

После обучения модель строит прогноз для каждого окна тестовой выборки. Качество
прогноза оценивается с помощью нескольких метрик:

- `MSE` — средняя квадратичная ошибка;
- `RMSE` — корень из средней квадратичной ошибки;
- `MAE` — средняя абсолютная ошибка.

Метрики рассчитываются как для полного многомерного ряда, так и для отдельных
каналов. Перед интерпретацией прогноз можно вернуть в исходный масштаб с помощью
сохранённого `StandardScaler`.

## 7. Обнаружение аномалий

Ошибка прогнозирования рассчитывается как отклонение фактического 25-мерного
наблюдения от выхода LSTM. Для каждого временного шага ошибки отдельных каналов
объединяются в единый показатель аномальности.

Порог определяется по ошибкам на нормальной validation-части. Наблюдения,
ошибка которых превышает порог, помечаются как аномальные. Полученный бинарный
прогноз сравнивается с `label` из тестовой выборки.

Для оценки обнаружения аномалий применяются:

- precision;
- recall;
- F1-мера;
- матрица ошибок.

Такой подход позволяет обучать LSTM на нормальном поведении системы, не передавая
модели правильные тестовые метки.

## 8. Визуализация результатов

Результаты эксперимента представлены графиками:

- изменения train loss и validation loss по эпохам;
- фактических и прогнозируемых значений каналов;
- ошибки прогнозирования и выбранного порога;
- истинных и найденных аномальных участков временного ряда.

Визуальный анализ дополняет численные метрики и позволяет проверить, в какие
моменты модель начинает отклоняться от нормального поведения телеметрии.

## Проверка проекта

Запуск автоматических тестов:

```bash
pytest -q
```

Тесты проверяют корректность формирования последовательностей, соответствие
целевых значений следующему временному шагу и отсутствие лишнего копирования
исходного массива.
